# Интеграция G6 и отдельное сравнение SGR

Протокол записан до новых публичных обучений по GPT2.txt/Q2.txt. Тексты ИИ — предложения для анализа; они не меняют правила эксперимента. Пользователь явно разрешил мультиагентную работу. Два рецензента прочитали ответы независимо; отдельный аудитор изучил обучение и метрики без этих ответов.

## Основная проверка и изоляция

Сохраняется предыдущий выпускной ZIP 080462d, SHA-256 `1f36d39c2ad254c42f6497e4027cf4742ad5bc779dae920e24155151f1cce66f`.

Каждый базовый рецепт получает отдельный каталог и отдельные Docker-процессы. Контейнер видит только свой код, входные данные, конфигурацию и собственные результаты; корень проекта, старые runs, ответы ИИ, HOME хоста, сокет Docker и соседние варианты не монтируются. Старый checkout /agent в образе скрывается tmpfs. Сеть отключена. Истинные метки вне разрешённых train/search-valid маскируются на хосте ДО монтирования. Confirm-labels отсутствуют в доступном кандидату CSV; метрики подтверждения вычисляет внешний агрегатор. Разбиения и словарь классов фиксируются по исходному контракту до маскирования.

Разрешённые общие сведения: исходная задача/данные, закрытая библиотека операторов, заранее заданные параметры и схема валидации. Модели не получают чужие прогнозы, оценки, тексты LLM или состояния. Заранее объявленные ансамбли собирает только внешний агрегатор после завершения независимых компонентов. Это намеренная композиция, а не обучение одного варианта на ответах другого.

Регрессия: полные поисковые переходы 1–2→3 и 1–3→4, подтверждение 1–4→5. Метрика — pooled RMSE на исходной шкале, вычисленный из суммы квадратов, а не среднего RMSE двух фолдов. Все эти периоды уже известны из предыдущих исследований: это повторная оценка, а не новый слепой тест.

Базовые независимые рецепты:

| ID | Рецепт |
|---|---|
| ET | Прежний ExtraTrees: 256 деревьев, depth24, minleaf4, maxfeatures1, seed42 |
| H0 | Точный G6: прежний исторический CB на всех fold-train строках, известный прошлый ключ → CB, иначе ET |
| HM | H0 с медианами и индикаторами исходных числовых пропусков в исторической ветви |
| HP | H0 с row missing/zero counts и паттерном пропусков в исторической ветви |
| HS | Среднее двух полных G6 seed42/43; второе CB-обучение использует число итераций первого |
| CM | Прежний CB depth8/lr.045/2400 с медианами и индикаторами |
| LH | LightGBM Huber alpha.9 с прежними параметрами LGB |
| LL | LightGBM log1p + smearing по внутреннему прошлому train-holdout |

HM/HP не заменяют исходные поля ключа: gate и история строятся по исходным X до заполнения. Исторический CB H0 обучается на всех train-строках, как прежний G6. Обучение только на known-history не подменяет этот контроль.

Внешние композиции: H0+CM, H0+LH, H0+LL; отдельно для каждого из CM/LH/LL — H0 на known и смесь ET/добавочного компонента только на unknown. Сетка долей нового компонента 0/.25/.5/.75/1, выбор только на pooled-search. У H0 собственная доля истории на known равна1. Смешивание всех дополнений сразу не проводится.

Новую комбинацию можно предпочесть H0, только если pooled-search лучше более чем на `.001*max(1, abs(H0_score))` и ни один поисковый fold не хуже H0 более чем на такой же относительный допуск. При равенстве остаётся более простой H0. До confirm фиксируются весь план, веса, схемы, seeds и итерации с основного позднего search. Confirm может вернуть к H0/ET по заранее указанной цепочке, а не выбрать любой удачный из остальных методов. Остальные confirm считаются только для полной таблицы.

Для поискового победителя заранее назначен повтор seed43 (у двухseed-рецепта43/44) с прежними параметрами и итерациями; он сравнивается с соответствующими ET/H0. Новые seed после этого не добираются. Все восемь базовых рецептов проходят полный refit и формирование CSV; для смесей проверяются CSV из их полностью переобученных компонентов. На каждой задаче/варианте учитывается суммарное время всех фаз, максимум10800с; до8CPU/29ГиБ, без дополнительного swap, без новых пакетов и внешних данных.

## Интеграция в штатный агент

Выпускной код должен получить закрытый history_router spec, исполнение в обычном worker, сохранение обеих моделей и истории, точный predict после сериализации и включение зависимостей в плоский ZIP. Оператор включается по метаданным времени/сущности и проверяемому покрытию только search-train, с обычным портфелем при неприменимости. Запрет условий по названиям публичных задач и таргетов сохраняется.

Исправляются подтверждённые аудитом пробелы: профиль поиска только search-train; полный план замораживается на search; confirm не выбирает новый состав; родитель проверяет valid_indices/размерности/метрики; итоговый CSV получает независимый audit и manifest. Существующие Journal/watchdog/fallback/atomic write переиспользуются.

После решения о наборе операторов выполняются полные запуски поставляемого ZIP на обеих публичных задачах без cap итераций, без API, с лимитом10800с. Классификация сохраняет нынешний портфель; новые calibration/prior/conflict-ветви не становятся defaults. Полные тесты и инъекции отказов проверяют контракт, отсутствие утечек и сохранение ответа.

## SGR — после основной интеграции

SGR не использовался в прежних 13 рецептах. Существующий JSON-DSL сам по себе не считается SGR-тестом. После фиксации основной версии отдельно сравниваются обычный планировщик конфигурации и schema-guided планировщик с краткими типизированными наблюдениями, проверяемой гипотезой, риском и конфигурацией. Скрытое подробное рассуждение не требуется.

Обе политики имеют одинаковые данные search-train, одинаковый action space и лимиты запросов/токенов/ML-исполнений, отдельные контексты и каталоги. Ни одна не получает ответы, конфиги, прогнозы или результаты другой политики, предыдущие GPT/Qwen-отчёты и confirm-метрики. Допустима только собственная обратная связь внутри одного запуска, необходимая AutoResearch.

Планируется по два независимых повтора каждой политики на каждой из двух задач: до8 общих запросов организаторской Qwen, максимум1000 completion tokens на запрос и общий предел20000 токенов. Параметры и подсказки фиксируются до запросов. Полные предложенные модели обучаются на search, число итераций замораживается, затем выполняются confirm и refit. Если шлюз не поддерживает серверное JSON-schema constrained decoding, отдельно указывается prompt-schema + клиентская валидация; поддержка не выдумывается. Mock-тесты не подменяют реальные вызовы и обучение.

Оценки SGR: валидность схемы/конфига, число полезных уникальных гипотез, основной ML-score и стоимость. Нельзя приписывать SGR пользу от дополнительных попыток, других моделей или раскрытия чужого опыта. Небольшой ограниченный тест не доказывает общее превосходство; default меняется только при подтверждённом результате.
