# Интеграция проверенных предложений GPT2/Q2

Состояние на **26 октября 2026 года, МСК**. В именах каталогов используется UTC, поэтому ночные запуски имеют дату `20261025T22…`. Все четыре полных old/new запуска регрессии и классификации завершены и независимо проверены. Реальных SGR-вызовов пока 0; полные финальные тесты v3 ещё выполняются.

В штатный агент внедрён `history_router`: для известного прошлого ключа он использует исторический CatBoost, для неизвестного — `0.5 × ExtraTrees + 0.5 × LightGBM Huber`. На подтверждении RMSE снизился с **41.751454 у H0 до 38.862101**. Это повторная оценка уже исследованных периодов, а не новый слепой тест.

Источники: [предварительный протокол](INTEGRATION_PROTOCOL.md), [компактные результаты](INTEGRATION_RESULTS.json), [полный журнал измерений](../runs/integration/20261025T220055/summary.json). В журнале сохранены SHA-256 исходных `GPT2.txt` и `Q2.txt`. Тексты рассматривались как предложения; решение принималось по измерениям. Проверялись обработка пропусков, устойчивость двух seed, робастная и логарифмическая регрессия, глобальное смешивание и смешивание только на неизвестных ключах.

**Решение по внедрению GPT2/Q2:** использовать строгую прошлую историю и unknown LH с α=.5; сохранить H0 как контроль. HM, HP и HS не включать в основной рецепт из-за результатов поиска; глобальные смеси дали α=0. Unknown CM/LL прошли порог допуска, но уступили LH. В классификации сохранить прежний сильный фиксированный ансамбль LightGBM63/CatBoost .5/.5. Новые calibration/prior/conflict-ветви и SGR пока не назначены defaults.

Каждый базовый рецепт обучался независимо в своём каталоге и Docker-процессе, без сети, чужих результатов, старых runs, LLM-текстов, HOME и Docker-сокета. Старый checkout образа закрывался tmpfs. Разрешённые метки маскировались на хосте до монтирования; confirm-метрики считал внешний агрегатор. Общими были задача, допустимые операторы, заданные параметры и схема валидации. Заранее объявленные смеси собирались снаружи после завершения компонентов.

Поиск использовал переходы `1–2 → 3` и `1–3 → 4`, подтверждение — `1–4 → 5`. Pooled RMSE рассчитан из суммарной квадратичной ошибки двух фолдов, а не усреднением их RMSE. План, схемы, веса, seed и число итераций заморожены [до confirm](../runs/integration/20261025T220055/frozen_before_confirm.json). Confirm мог только подтвердить победителя либо вернуть контроль по заданной цепочке; остальные строки confirm приведены для полноты.

В таблице α — доля добавочного CM/LH/LL. `global` смешивает его с H0 на всех строках; `unknown` сохраняет H0 на известных ключах и смешивает компонент с ET только на неизвестных. Сетка α: `0 / .25 / .5 / .75 / 1`. Меньший RMSE лучше.

| H0: исходный G6 | — | 52.068992 | 33.691280 | 43.067073 | 41.751454 | Контроль |

| HS: среднее G6 seed42/43 | — | 51.714123 | 34.238794 | 43.106443 | 41.826950 | Отклонён |

H0 обучает исторический CatBoost на всех fold-train строках: известное прошлое → CB, иначе прежний ET. HM/HP меняют только историческую ветвь; ключ и история строятся по исходным X до подстановки. HS усредняет два полных маршрутизатора. CM — CatBoost depth8/lr.045/2400 с медианами и индикаторами; LH — LightGBM Huber alpha.9; LL — LightGBM log1p со smearing, оценённым на внутреннем прошлом holdout.

Для замены H0 требовалось улучшение pooled search более `0.001 × max(1, |H0|)` и отсутствие ухудшения любого поискового фолда сверх такого же относительного допуска. Поэтому лучший pooled HP не прошёл ограничение позднего фолда. Из допустимых методов unknown LH выиграл поиск до раскрытия confirm. Его подтверждённое улучшение относительно H0 — **2.889353 RMSE**; записанный условный 95% интервал улучшения — `[2.390071; 3.386285]`. Он не превращает повторно изученные периоды в независимый тест.

Наконец, первый проверочный search-скрипт сравнивал фиксированное число итераций истории с ранней остановкой; исправлен режим проверки, допуск сравнения не ослаблялся. Оператор применим к регрессии при числовом упорядоченном периоде и ключе сущности, выводимом из метаданных: явном, составном либо из описанных стабильных атрибутов. Покрытие проверяется только на search-train. Совпадение атрибутов не доказывает идентичность физического объекта; коллизии и неоднозначные группы диагностируются. Пропуск части ключа запрещает сопоставление, история использует только строго более ранние периоды. Для произвольного текста даты и недостаточного описания ключа универсальность не доказана; при неприменимости работает обычный портфель. Условий по имени публичной задачи или таргета нет.

В runtime поиск профилируется только по search-train, весь выбранный план замораживается до confirm, родитель проверяет индексы, размеры и метрики. Сохраняются модели, история, политики и конфигурация; итоговый CSV проходит независимый audit и manifest. Сохраняются Journal, watchdog, fallback и атомарная запись.
