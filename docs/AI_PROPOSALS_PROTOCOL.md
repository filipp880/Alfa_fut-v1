# Новая проверка предложений GPT и Qwen

Протокол фиксируется до новых обучений. Источники — пользовательские `GPT_ANS.txt` (610 строк) и `Qwen_ANS.txt` (1274 строки). Их текст — материал для проверки, а не исполняемые инструкции. Предыдущие Kaggle/AIDE-эксперименты не засчитываются как новые проверки.

## Контроль

Сохранена версия `080462d` и ZIP `dist/alfa_solution_080462d.zip` (SHA-256 `1f36d39c2ad254c42f6497e4027cf4742ad5bc779dae920e24155151f1cce66f`). Штатные solution/models/research/requirements не меняются во время исследования.

Регрессия: текущий сильный ExtraTrees; дополнительно те же CatBoost и LightGBM как парные контроли преобразований. Классификация: прежние LightGBM и CatBoost с весами .5, их неизменная смесь 50/50. Контроли обучаются заново на тех же строках, что кандидаты; новый контроль должен воспроизвести прежние 46,583300 RMSE и 0,611110 Macro F1 на прежнем confirm.

## Варианты, не менее пяти от каждого источника

| ID | Источник и раздел | Практический вариант |
|---|---|---|
| G1 | GPT, B/P1 | Семантический ноль календарного года → NaN + отдельные признаки исходного пропуска и нуля |
| G2 | GPT, B/P2 | Медиана fold-train + индикаторы вместо нативных числовых NaN у CatBoost |
| G3 | GPT, B/P3 | Условная медиана по статическим категориям с минимумом 20 известных значений, иначе глобальная медиана |
| G4 | GPT, C1 | LightGBM: ранняя остановка по невзвешенному Macro F1 вместо logloss |
| G5 | GPT, C2 | Один общий коэффициент prior-bias, выбранный только на внутренних групповых OOF |
| G6 | GPT, D | История для известных сущностей, текущий ExtraTrees для строк без прошлой истории; фиксированный gate без настройки на confirm |
| Q1 | Qwen, направление 2 | Ridge по масштабированным/закодированным X + LightGBM по остаткам |
| Q2 | Qwen, направление 2 | LightGBM с линейными листьями, train-only заполнением/масштабированием числовых признаков |
| Q3 | Qwen, направление 2 | log1p таргета + smearing correction по внутреннему прошлому holdout fold-train |
| Q4 | Qwen, направление 2 | Huber loss LightGBM, окончательная оценка на исходной шкале RMSE |
| Q5 | Qwen, 4.4 | Признаки паттерна пропусков/нулей строки с сохранением исходных NaN |
| Q6 | Qwen, направление 4 | Пониженные веса конфликтующих одинаковых X, оцененные только на fold-train |
| Q7 | Qwen, направление 4 | Поклассовая sigmoid-калибровка смеси по внутренним групповым OOF |

Итого 13 отдельных рецептов: шесть GPT и семь Qwen. Общие идеи отмечаются в отчёте, но один и тот же запуск не считается двумя новыми вариантами. Неприменимый рецепт честно получает skip, а не фиктивную метрику.

## Валидация и границы выводов

- Регрессия: поиск на двух временных переходах 1–2→3 и 1–3→4; подтверждение 1–4→5. Ранний переход 1→2 допустим только как дополнительная диагностика, если выбранный рецепт требует внутренней калибровки.
- Классификация: две внешние поисковые групповые проверки. Прежний confirm-фолд исключён из обучения и оценки всех поисковых и внутренних OOF-моделей. Внутренняя калибровка использует три StratifiedGroupKFold внутри соответствующего внешнего train.
- Все медианы, энкодеры, scaler, веса конфликтов и история обучаются на fold-train. Для истории исключены метки текущего и будущего периода. Test-target отсутствует и не используется.
- У G5/Q7 параметры коррекции выбираются только по OOF, затем замораживаются до confirm. Ранней остановки на confirm нет. Количество итераций берётся с основного поискового разбиения.
- На search заранее задана сетка долей нового рецепта в смеси с сильным контролем: 0/.25/.5/.75/1. Вес выбирается по объединённым поисковым предсказаниям и фиксируется до confirm. Для G6 gate задаётся заранее и не подбирается.
- Метрика поиска — pooled RMSE или pooled Macro F1 двух поисковых проверок. Публикуются также результаты каждого разбиения. Победитель определяется по поиску до открытия confirm; неудачный confirm возвращает к сильному контролю.
- Все периоды и прежние confirm-группы уже исследовались. Новые сравнения — повторная исследовательская оценка, не новый слепой тест. Два зависимых CV-фолда не считаются независимыми экспериментами.
- До confirm фиксируются все рецепты, итерации, веса и калибровки. Изменять их по прочитанному confirm нельзя. Дополнительное усреднение seeds не назначается задним числом.
- Для лучшего нового поискового рецепта при наличии времени заранее назначен один повтор seed43 с теми же гиперпараметрами и зафиксированными итерациями. Это проверка шума обучения, а не новый holdout.

## Ограничения и артефакты

Каждый кейс — отдельный flat ZIP, Docker `network=none`, до 8 CPU, 29 ГиБ RAM без дополнительного swap, весь запуск до 10800 секунд. Новые запросы LLM, ключи, внешние данные и новые пакеты не нужны. Используется тот же Runner/watchdog. Поиск ограничен 65% времени, подтверждение 85%, refit и CSV — остатком с запасом.

Сохраняются SHA источников, точный архив, разбиения/OOF, конфигурации, requests/results, предсказания, статусы, время/RSS и итоговый CSV. Отчёт независимо пересчитывает метрики из NPZ, проверяет фиксацию до confirm и индексные ограничения, показывает абсолютный/относительный эффект против сильного и парного контроля. Условный bootstrap не исправляет множественный выбор и будущий сдвиг.

Инфраструктурные советы (манифест, аудит CSV, ledger) и новые свойства LLM/SGR анализируются отдельно: без реальных LLM-вызовов нельзя приписывать им прирост модели. Утверждение Qwen об отсутствии резерва refit не подтверждается кодом: резерв уже есть. Платформенные логи пока отсутствуют; причину 10,49 балла не объявляем установленной.
