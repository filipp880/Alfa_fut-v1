# Проверка новых идей Kaggle и AIDE в Alfa_fut-v1

## Что проверяется

Исследование продолжает незавершённое поручение из `HANDOFF.md`. Новые проверки — история повторяющихся сущностей, модельная импьютация, групповой PCA, direct XGBoost и ограниченный поиск по дереву конфигураций. Ранее завершённые ExtraTrees/Nyström/kNN используются как часть контекста и сильного контроля, но не выдаются за новые результаты.

Методика до запуска описана в [KAGGLE_PROTOCOL.md](KAGGLE_PROTOCOL.md). Полные машинные результаты сохраняются в `KAGGLE_RESULTS.json`; метрики пересчитывает `tools/report_kaggle.py` из сохранённых предсказаний.

## Первоисточники и ограничения воспроизведения

- [Разбор Leonie](https://www.kaggle.com/competitions/widsdatathon2022/writeups/leonie-solution-writeup) при текущей проверке не вернул доступный текст. Ранее прочитанное описание из handoff служило отправной точкой; конкретные детали повторно не подтверждены этим URL.
- [Исходный notebook Imputers](https://github.com/nd265/wids-2022-datathon/blob/main/src/wids-2022-datathon-imputers.ipynb) прочитан как JSON, без исполнения и без CSV. В нём есть составной ключ, PCA погодных групп, IterativeImputer с ExtraTrees и ансамбль нескольких семейств. Его групповые средние таргета до CV создают утечку локальной оценки; эта часть заменена строго прошлой историей. GPU-настройки и многотысячные конфигурации не копируются на наш CPU-стенд.
- [Указанный UNSW-NB15 writeup](https://www.kaggle.com/competitions/advanced-ai-for-cybersecurity-intrusion-detection-with-unsw-nb-15/writeups/new-writeup-1776760930392) текущим инструментом недоступен. XGBoost проверяется как самостоятельная гипотеза. Native API и категории сверены с официальными исходниками [training.py v2.1.4](https://raw.githubusercontent.com/dmlc/xgboost/v2.1.4/python-package/xgboost/training.py), [документацией категорий](https://raw.githubusercontent.com/dmlc/xgboost/v2.1.4/doc/tutorials/categorical.rst) и [параметров](https://raw.githubusercontent.com/dmlc/xgboost/v2.1.4/doc/parameter.rst). Inverse-square-root веса — наша гипотеза, а не приписанная автору настройка.
- Из AIDE изучены [agent.py](https://raw.githubusercontent.com/WecoAI/aideml/main/aide/agent.py) и [journal.py](https://raw.githubusercontent.com/WecoAI/aideml/main/aide/journal.py). Они подтверждают принцип начальных решений, исправлений и улучшений с хранением связей узлов. [MLE-bench](https://openai.com/index/mle-bench/) — источник контекста оценки ML-агентов; его результаты не доказывают прироста нашей реализации с Qwen.

Оригинальные Kaggle-данные и ответы не скачивались. Результаты Kaggle не сравниваются численно с нашим другим разбиением.

## Как адаптирован AIDE

Текущий поток: TaskReader → профиль/разбиения → очередь Research и предложения ограниченного LLM-DSL → Runner/worker → выбор одиночных финалистов и комплементов → замороженные смеси → подтверждение без ранней остановки → refit/CSV. После очереди нынешний Research уже изменяет лучшую успешную конфигурацию. Ограничение состоит в отсутствии явного графа происхождения, учёта исследованных ветвей и общей истории исправлений.

Экспериментальный `BoundedSearch` добавляет граф `конфигурация → одно изменение → результат`. Узел хранит ID родителя и потомков, действие, конфигурацию и её fingerprint, статус, метрику, длительность, ошибку и каталог артефактов. Python-код от LLM не исполняется: разрешены только атомарные изменения проверяемых полей ExperimentSpec. Зависимость aideml не устанавливается.

В эксперименте один общий Qwen-запрос предлагает пул действий. Неверные действия отбрасываются, добавляется встроенный безопасный резерв. Обе политики получают одинаковый пул, его порядок для данного seed, начальную модель, шесть fit-попыток, общий временной предел и индивидуальный предел обучения. Внутри политик дополнительных LLM-вызовов нет. Фактическое время может различаться и измеряется отдельно.

Линейная политика продолжает последнюю успешно исполнившуюся модель, даже если её качество ухудшилось. Дерево обычно выбирает лучшую метрику; с вероятностью 0,2 возвращается к успешной ветви с меньшим числом потомков. После ошибки обе политики имеют одинаковую возможность одного исправления через уменьшение ресурсоёмкости; бесконечные цепочки ремонта запрещены. Повторные конфигурации исключаются. `observe()` обязателен до следующего `next()`.

Пример механизма, не экспериментальные числа: модель с меньшим шагом улучшила search; последующее увеличение глубины ухудшило результат. Цепочка развивает последнюю модель, а дерево может вернуться к варианту с меньшим шагом и проверить другую регуляризацию. Подтверждающая метрика на этом шаге недоступна. После поиска конфигурации, число итераций и веса фиксируются; только затем открывается confirm.

Практическая интеграция при наличии доказанного выигрыша: `research.py` выбирает планировщик, `solution.py` передаёт ему результаты через `observe()`, `experiment_store.py` сохраняет граф, упаковщик добавляет `aide_search.py`. Изоляция, watchdog, метрики и безопасный CSV уже предоставлены `runtime.py` и worker. В эксперименте выбран более узкий вариант: самостоятельный исследовательский модуль и тот же Runner. Дополнительные расходы — шесть обучений на политику и seed; один Qwen-пул общий, а не отдельные запросы на каждый узел.

Победа над линейной цепочкой сама по себе не означает превосходства над нынешним Research: его уточнение уже использует лучшую модель. Для внедрения нужны устойчивый выигрыш против сильного текущего портфеля и перенос на подтверждение. Два seed планировщика — проверка ограниченной абляции, не масштабное доказательство архитектуры AIDE.

## Регрессия: основное сравнение

Сильный контроль выбирает ExtraTrees с подтверждающим RMSE **46,583300**. Это нынешнее решение, а не старый одиночный CatBoost 48,678636. Поиск портфеля получил лучшую замороженную смесь 42,211330; подтверждение выбрало одиночный лес. Базовый бустинг для одинаковых абляций — CatBoost с search 43,113298.

Прирост в таблице — уменьшение подтверждающего RMSE относительно сильного контроля; положительный знак означал бы улучшение. Время одиночных гипотез — search + confirm, без общего контроля, планировщиков и refit.

Комбинация нескольких преобразований не запускалась: заранее заданный критерий требовал минимум два отдельных улучшения search на 0,1%, а прошла только история. Это запланированное условие, не скрытый отрицательный опыт. PCA добавлялся к исходным X; варианты замены исходных признаков компонентами не проверялись. Импьютация проверяла весь блок «восстановление + индикаторы», поэтому отдельный эффект модельного восстановления от индикаторов не приписывается.

История относительно сильного контроля имеет условный 95%-интервал выигрыша **[−1,140; +1,091]**. Внутри фолда нет убедительного превосходства. У новых гипотез отрицательные результаты сохранены; никаких утверждений о непригодности XGBoost/PCA вообще из одной конфигурации не делается.

Основной запуск: **45 обучений/подтверждений/refit, 699,903 с**, максимальный worker RSS **766,78 МиБ**. Сеть ограничена организаторским шлюзом через CONNECT; один общий Qwen-запрос, **859 токенов**. Финальный refit ExtraTrees завершился, CSV содержит все 22449 тестовых строк.

### Что произошло с историей

Последующий описательный разбор сохранён в [KAGGLE_HISTORY_DIAGNOSTICS.json](KAGGLE_HISTORY_DIAGNOSTICS.json). На search история покрывает 76,68% строк, на confirm — 68,55%. Для известных сущностей confirm RMSE улучшился с 33,4426 у леса до 22,2668 у истории. Для неизвестных — ухудшился с 66,8029 до 76,3844. Выигрыш на известных почти полностью компенсирован проигрышем на неизвестных. Последние составляют 31,45% строк, но дают 84,37% суммы квадратов ошибок модели истории.

Это объяснение получено после просмотра confirm. Оно мотивирует будущую проверку резервной модели для неизвестных сущностей, но не даёт права задним числом считать такой маршрутизатор подтверждённым улучшением. Составной ключ также не доказывает физическую идентичность зданий: найденные неоднозначные группы публикуются в диагностике.

### Зависимость от seed

Заранее назначенный повтор seed43 с прежними гиперпараметрами и итерациями дал 46,770190 у контроля и 42,397945 у истории, тогда как основной seed42 дал 46,583300 и 46,632569. Это существенная дисперсия обучения истории, а не новый независимый тест и не разрешение выбрать seed43 по confirm. После её обнаружения зарегистрированы ровно seeds44/45 и фиксированное равновесное среднее четырёх seed для обеих ветвей; результаты будут добавлены после их выполнения.

## Что взять в проект

- **Оставить в штатном агенте:** нынешний портфель CatBoost/LightGBM/ExtraTrees и действующий поиск комплементов. Новые схемы не включаются автоматически.
- **Использовать в исследовании сейчас:** воспроизводимый стенд новых гипотез, безопасные fold-transformers, XGBoost-worker, граф происхождения экспериментов, фиксацию планов до confirm и независимый пересчёт по NPZ. Эти инструменты дают возможность проверять идеи, но сами по себе не объявляются приростом качества.
- **Исследовать дальше:** историю как ограниченного эксперта для известных сущностей с резервом на неизвестных и заранее зафиксированным многопериодным сравнением; учитывать чувствительность к seed. Это направление объясняет наблюдаемые ошибки, но ещё не подтверждено как улучшение всей системы.
- **Не включать по текущим данным:** проверенные конфигурации импьютации, PCA и XGBoost; замену нынешнего поиска деревом. Иные настройки или задачи могут дать другой результат.

В основных сравнениях выполнено **88 запусков**, оба полностью уложились в 10800 секунд. Исходный requirements не изменён; установленные версии проверены. Ни Kaggle, ни платформа хакатона не получали submission.

Усреднённая история снизила ошибку на **5,9466%** относительно симметрично усреднённого контроля. Условный групповой 95%-интервал уменьшения RMSE **[1,7140; 3,9155]**. История заметно менее стабильна по seed: стандартное отклонение RMSE 1,7421 против 0,2638 у леса.

Это реальный измеренный эффект на данном периоде, но проверка четырёх seed назначена после открытия основного confirm. Интервал не исправляет этот последующий выбор и не учитывает будущий сдвиг. Результат стоит развивать как исследовательский кандидат; автоматически считать 43,992874 качеством нового штатного агента нельзя. В исходном зафиксированном сравнении история seed42 не выиграла. Дополнительные шесть регрессионных fit заняли около 98 секунд целиком с чтением и проверками; новых API-вызовов не было.

Классификационный повтор seed43 с прежними параметрами, итерациями и весами подтвердил направление: контроль **0,612668**, новый план **0,602879**. Условный интервал разницы **[−0,02810; +0,00444]** включает ноль. Ни модель, ни смесь не выбирались по этому повтору. Независимый пересчёт: [KAGGLE_CLASSIFICATION_REPEAT_RESULTS.json](KAGGLE_CLASSIFICATION_REPEAT_RESULTS.json).

Вместе с четырьмя fit классификационного повтора выполнено ещё **10 обучений** сверх 88 основного исследования. Отсутствие сохранённого `docker inspect` для раннего регрессионного seed43 честно отмечено в JSON; команда использовала `network=none`, а счётчики API нулевые. Для новых повторов и классификации фактические ограничения сняты с активных контейнеров.

## Итоговое сравнение и вердикт

| Задача | Сильный нынешний контроль | Лучший новый замороженный отбор | Итоговый сохранённый агент | Изменение штатного качества |

| Регрессия, RMSE | 46,583300 | 46,632569 | 46,583300 | 0 |
| Классификация, Macro F1 | 0,611110 | 0,604109 | 0,611110 | 0 |

Это сравнение восьми заранее заданных контрольных конфигураций с ExtraTrees и действующим выбором смесей, а не оценка всех возможных 18 шагов штатного агента с другими LLM-предложениями. Подтверждающие данные уже были исследованы раньше. Балл платформы и качество скрытого теста не измерялись.

1. В основном протоколе ни одна новая идея не дала подтверждённого улучшения сильного нынешнего решения. Наибольший дополнительный измеренный эффект — равное усреднение четырёх моделей истории, с оговоркой о последующем выборе проверки.
2. Для регрессии в основном протоколе лучшим остаётся ExtraTrees; для классификации — уже существующий ансамбль LGB/CB 50/50. Новый ансамбль XGB/LGB 25/75 оказался слабее.
3. Постоянно расширять штатный портфель по этим результатам не следует. Реализованные новые модели и дерево остаются воспроизводимыми исследовательскими инструментами.
4. AIDE-подобный граф полезен для происхождения гипотез, возврата и учёта ошибок. Доказательств прироста качества против действующего AutoResearch здесь нет: регрессия ухудшилась в одной паре, классификация дала небольшой выигрыш над цепочкой в одной паре и равенство в другой.
5. Следующая наиболее обоснованная проверка — заранее зарегистрированная история с резервом для неизвестных сущностей и фиксированным усреднением seed на нескольких временных переходах. Текущий разбор показывает механизм возможной пользы; его ещё нужно проверить до замены дефолта.
