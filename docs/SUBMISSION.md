# Загрузка решения на платформу

Для v4 загружайте [alfa_solution_v4_2026-10-27.zip](../dist/alfa_solution_v4_2026-10-27.zip).
В нём 23 корневых Python-модуля и исходный `requirements.txt`, всего 79 080 байт.
`solution.py` находится в корне архива. README, данные и обученные веса для
запуска не нужны и в архив не входят. Загрузка одного `submission.csv` вместо
ZIP не проверяет агента: платформа сама запускает его на своих задачах.

## Проверка скачанного файла

SHA-256 опубликован [рядом с архивом](../dist/alfa_solution_v4_2026-10-27.zip.sha256):

```text
ce4d46965cc4f13eae67e0eeb0033c284bf6e9e3cbe48c9782964a3d2ea15708
```

Из корня репозитория в PowerShell:

```powershell
Get-FileHash -Algorithm SHA256 .\dist\alfa_solution_v4_2026-10-27.zip
```

Совпадение подтверждает, что выбран испытанный архив. Его не нужно
распаковывать и заново упаковывать перед отправкой.

## Что запускает платформа

```bash
python3 solution.py task.md
```

Материалы задачи доступны через условие и файлы рядом с ним. Итоговый
`submission.csv` записывается рядом с `task.md`; `submission.manifest.json`
содержит результат проверки CSV, число строк и контрольную сумму.
Ключ и настройки LLM передаются окружением проверяющей среды, в ZIP ключа нет.
Без доступного LLM агент использует локальный исследовательский портфель.

## Что сохранить после проверки

Сохраните имя архива и SHA-256, идентификатор отправки, итоговую оценку и полный
текст журнала. При замечаниях LLM нужны строки `llm_config`, `llm_skipped` и
`llm_error` без ключей. При ошибке модели — её фаза, тип ошибки и traceback,
если судьи его предоставляют. Итоговый `finished` показывает источник
предсказаний, завершение refit, использование резерва и число строк CSV.

Локальные RMSE/Macro F1 и результаты синтетики не являются баллами платформы.
