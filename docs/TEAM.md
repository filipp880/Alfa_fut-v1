# Разделение поддержки между тремя разработчиками

Общие контракты меняются согласованно. Владелец контракта — разработчик 1.
Модули для сдачи остаются в корне, папки тестов и документации в ZIP не нужны.

| Участник | Сложность | Владение | Порядок работ | Готовность |
|---|---|---|---|---|
| 1 | Наибольшая | solution, contracts, research, llm_client, runtime, experiment_store | Контракты → управление → лимиты → LLM → интеграция | Сбой API/worker не уничтожает CSV, поиск воспроизводим по журналу |
| 2 | Средняя | models, preprocessing, validation, metrics, worker | Метрики → разбиения → CatBoost → LightGBM → подтверждение | Нет утечек, верная метрика, неизвестные категории работают |
| 3 | Наименьшая | task_reader, data_io, submission, tools, tests, документация | Чтение → формат → ZIP → аварийные тесты → инструкция | Чистая распаковка запускается через интерфейс платформы |

Для оставшихся двух дней: первый день посвятить анализу журналов и улучшениям
моделей, второй — проверкам на лимитах и интеграции. Последние 6–8 часов до
дедлайна оставить на полные прогоны, исправления и отправку. Новые семейства
моделей добавлять только при подтверждённой выгоде, после сохранения рабочего ZIP.
