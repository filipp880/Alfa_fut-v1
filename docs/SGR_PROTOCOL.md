# Отдельный SGR-тест после основной интеграции

Этот подпротокол фиксируется до новых реальных запросов к шлюзу. Основные модели и выпускной ZIP сначала проходят полные проверки. Основание SGR: [описание автора](https://abdullin.com/schema-guided-reasoning/) связывает заданную структуру шагов с constrained decoding; один JSON-конфиг прежнего агента не считался SGR.

Сравнение: обычный `LLMPlanner` и `SGRPlanner` с серверным `response_format=json_schema`, `strict=true` и клиентской проверкой. Схема содержит до трёх кратких observations, проверяемую hypothesis, risk, verification и полный ExperimentSpec. Подробный скрытый ход рассуждений не запрашивается. Проверка структуры не доказывает истинность текстового наблюдения.

Action space одинаков: фактические 15 полей ExperimentSpec, CatBoost/LightGBM/linear, прежние диапазоны и закрытые преобразования. SGR не получает дополнительные модельные семейства. Шлюз/модель одинаковы: `https://api.alfahack-gateway26.ru/v1`, `qwen/qwen3.8-27b`. Ключ читается только процессом запросов из внешнего файла, не печатается и не попадает в ML-контейнеры.

Две задачи × два независимых повтора × две политики = **максимум8 запросов**, по одному предложению на контекст, максимум1000 completion tokens каждый. Истории пустые: оценивается ограниченный парный тест одного предложения, а не превосходство всего многошагового AutoResearch. Повторы используют одинаковые ML-seed42/43 для обеих политик; seed ответа нормализуется и сохраняется отдельно от исходного предложения. Температура0,15, thinking отключён одинаково. Порядок политик чередуется между задачами/повторами.

Общий токенный предел уточнён до **40000** вместо предварительных20000 в общем протоколе: полная серверная схема увеличивает входной контекст. Это уточнение сделано до вызовов и не зависит от результатов SGR. Учёт фактических usage либо консервативной оценки, остановка при исчерпании бюджета. Повторных скрытых запросов/retry нет. Ошибка схемы, шлюза или пустой ответ учитываются как неудача, а не заменяются вымышленным предложением. Если сервер отклоняет JSON Schema, это ограничение совместимости; prompt-only имитация не называется полным SGR.

Каждая политика получает одинаковые task excerpt, словарь допустимых признаков/классов, профиль только search-train и остаток времени. Ни одна не получает GPT2/Q2, предыдущие отчёты, другую политику, чужие конфиги/прогнозы/оценки, confirm-метрики. Запросы stateless, каждый состоит только из собственного system/user payload. Сохраняются точные prompt/schema, ответы в проверенном виде, версии и usage. Вызовы начинаются после фиксации основной версии.

Для каждого валидного предложения выполняются полные main-search, confirm и refit в отдельных контейнерах через тот же стенд. Регрессия: main-search1–3→4, confirm1–4→5. Классификация: фиксированные групповые search/confirm, без пересечения одинаковых X. На confirm реальные y скрыты из CSV; оценка производится снаружи. На refit весь train разрешён. Профили и преобразования fit-only, число итераций берётся с search; ограничения10800с/8CPU/29ГиБ на вариант, без скачивания пакетов и внешних данных.

Контроль — новый основной агент, полностью проверенный и зафиксированный **до SGR**. Его прогнозы доступны только внешнему агрегатору; кандидаты и LLM их не видят. Допустимый эффект AutoResearch-предложения оценивается отдельно и в смеси с этим контролем. Доля0/.25/.5/.75/1 выбирается на main-search с допуском `.001*max(1,abs(score))`, замораживается до confirm. На confirm можно лишь вернуться к контролю. Все валидные кандидаты обучаются до полного refit, даже если поиск выбрал долю0. Контроль заново не меняется по SGR-результатам.

Отчёт: валидность/уникальность гипотез, standalone и frozen-blend метрика, время, токены, ошибки, работающий CSV. RMSE пересчитывается вручную на исходной шкале; Macro F1 — через полную confusion matrix. Периоды/группы уже исследованы ранее; два повтора на тех же данных не являются независимыми новыми тестами. Ограниченный результат не доказывает общего превосходства SGR. По умолчанию сохраняется обычный планировщик, пока результаты не дают оснований менять его; SGR доступен явным `--planner sgr`.
