# Ранние линейные модели и OOF-ансамбль: протокол

Зафиксировано до новых публичных прогонов, 26 октября 2026 года.
Контроль — проверенный v3, SHA-256
`752afaae4fa813879bb301d7464924d9217a77999502ce10aa764ee36ed35483`.

Изменение1: обязательный первый кандидат `linear`: Ridge для регрессии,
логистическая регрессия для классификации. Препроцессоры fit-only как прежде.
Для редких F1-классов используется прежняя умеренная степень весов0,5;
для текста regularization1, иначе5. Уточнение линейного лидера меняет только
существенные параметры регуляризации/весов, без фиктивных вариантов глубины.
Ранний plateau-stop допускается после проверки существенных контролей,
чтобы новая первая модель не вытеснила прежний сильный исторический маршрут.

Изменение2: три широких семейства — бустинг (лучший CatBoost/LightGBM),
ExtraTrees и linear. Composite history_router/proposal не участвуют в OOF;
сильный исторический план сохраняется кандидатом/контролем.
OOF только внутри search.train, до трёх folds. Для повторов — группы,
для классификации — стратификация; для времени — расширяющееся прошлое.
Временной первый блок — warmup, не мета-выборка. Нужно минимум два folds;
при недостатке независимых классов/групп OOF пропускается.

Все параметры/итерации берутся из search до OOF, в OOF refit=True:
на OOF-valid нет early stopping. Каждый fold имеет собственные fit-only
профиль и преобразования. Все три члена имеют одни и те же OOF-valid индексы.
Мета-веса обучаются только на OOF-valid и исходной метрике TaskSpec.
Simplex grid: шаг0,1 + равные1/3 + парные0,25/0,5/0,75; веса>=0, сумма1.
Нулевые веса допустимы; третий слабый член не добавляется принудительно.

Замороженные OOF-веса отдельно проверяются на search.valid. При улучшении
более `.001*max(1,abs(score))` новый план сравнивается на confirm с результатом
ПРЕЖНЕГО правила: сначала legacy search-план против legacy-контроля, затем
OOF против полученного guard. Все три плана и их веса/counts фиксируются ДО
confirm, guard-члены проверяются первыми. Это сохраняет прежний полезный
fallback даже при неудачном новом плане или нехватке времени на его confirm.
Если OOF не принят, прежние правила planned/control сохраняются.
После confirm только полный refit выбранного плана; при сбое прежний CSV.

OOF ограничен концом70% общего бюджета и максимум12% времени задачи;
есть оценка стоимости до fit, последовательные worker, общий watchdog10800с,
8CPU/32ГБ. Недостаток времени/ошибка fold → OOF discard, рабочий план сохранён.

Сравнения: A=v3 сохранённые полные артефакты; B=ранний linear без OOF
(`--no-oof`); C=linear+OOF по умолчанию. B/C на двух полных публичных задачах,
max18,10800с,без iteration cap,без API. Отдельные case/контейнеры без сети,
по4CPU14ГиБ, суммарно8CPU28ГиБ. Дополнительно реальные синтетические задачи
и тесты train/valid/groups/time/label perturbation/весов/CSV/дедлайна.
Базовые модели не получают чужие прогнозы; объединение только во внешнем
контроллере ансамбля. Чужие отчёты/ответы LLM не передаются вариантам.

Отчёт разделяет эффект раннего linear и OOF, фактическое число семейств
с ненулевыми весами, качество search/confirm, все fit/время/ошибки и full CSV.
Известные публичные разбиения не являются новым blindtest; баллы приватной
платформы не предсказываются из локальных метрик.
