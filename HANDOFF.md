Создать универсального AI-агента для хакатона Альфа: он читает описание неизвестной ML-задачи и данные, выбирает подход, генерирует и запускает эксперименты, анализирует результаты в цикле AutoResearch, обучает итоговую модель и сохраняет submission.csv. Нужны сильные результаты на скрытых данных, надёжность и соблюдение ТЗ.

- ВСЕ сообщения, объяснения и отчёты — на русском.
- Пользователь просит действовать автономно, сначала обоснованно сравнивать подходы, затем реализовывать и проверять лучшие. Не нужны постоянные вопросы о разрешении и длинное планирование.

- Пользователь просил не делать «этап 4» старого метапромта — финальный план в JSON. Машинные журналы и фактические JSON-результаты разрешены и уже используются.
- Весь код должен быть в https://github.com/filipp880/Alfa_fut-v1.git. Проверенный код уже публиковался в main; разрешение на работу с этим репозиторием сохраняется.

## 6. Реализация в опубликованном faedd2a

16 корневых runtime-модулей:
solution, contracts, task_reader, data_io, validation, metrics, submission, preprocessing, models, worker, runtime, experiment_store, research, llm_client, novel_models, novel_worker.

- TaskReader определяет контракт по тексту, словарю, train/test и sample; сохраняет id строками. Если указанный в task.md путь отсутствует, ищет файл по имени рядом с задачей.
- CatBoost/LightGBM, TF-IDF + линейная модель для текста, один ограниченный ExtraTrees-кандидат в обычном агенте.
- novel_models.py также содержит исследовательские Nyström+регуляризованную модель и взвешенную память соседей. Они по умолчанию не включены в основной поиск.
- Все преобразования обучаются только на fit-части; неизвестные категории и пропуски обрабатываются.
- LLM возвращает ограниченный JSON-DSL, не произвольный исполняемый код. Стандартный ExperimentSpec допускает CatBoost/LightGBM/linear; parse_experiment — закрытый реестр альтернатив.
- Из проверенного config генерируется фиксированный experiment.py. Отдельный процесс с watchdog по времени/RSS; ключа API в нём нет.
- Резервный CSV записывается рано и атомарно. Ошибка/недоученный refit не затирает проверенный ответ.
- choose_finalists в research.py ищет лидера и ДО ДВУХ полезных дополнений из разных семейств по метрике СМЕСИ на поиске. Не просто две лучшие самостоятельные модели.
- Веса смеси (.25/.5/.75) и число итераций фиксируются в finalists.json ДО подтверждения. На подтверждении нет early stopping: refit=True и fixed_iterations из поиска.
- Затем выбирается лучший подтверждённый одиночный кандидат или одна из заранее зафиксированных смесей. Это ограниченный отбор, а не независимая оценка скрытого теста.
- Финальный refit на всех данных выполняется при наличии резерва.
- Research(..., include_alternatives=False) сохраняет старый портфель для исследовательских КОНТРОЛЕЙ. Штатный solution.py передаёт True.
- ExtraTrees-кандидат ограничен по оценке размера плотной матрицы и отсутствию текстовых полей; нет if по имени датасета/таргета.

## 10. Как продолжить последнее поручение

Это рекомендации следующему агенту, а не уже реализованные компоненты:

1. Сохранить текущий сильный контроль faedd2a и ZIP. Новые идеи сравнивать с НЫНЕШНИМ агентом, включая ExtraTrees и поиск комплементов, а не только со старым CatBoost 48,68.
2. Заранее записать небольшой набор гипотез и критерии: идентичность сущности/прошлая история, модельное восстановление пропусков, групповой PCA, XGBoost, затем полезные комбинации. Часть идей неприменима к классификации без времени/пропусков — честно записывать skip по структуре данных.
3. Для entity/history нельзя использовать validation/test target. Для обучающих строк статистика должна быть OOF/строго из прошлых периодов, а не groupby(target).mean() на всём train. Проверять коллизии составных ключей, неизвестные группы и долю совпадений.
4. Имьютеры обучать только на известных значениях признака внутри fold-train, используя другие X, без таргета/id. Сравнить с сохранением NaN/индикатора; не считать заполнение улучшением заранее. PCA fit/scale только на fold-train.
5. Схемы признаков можно предложить Qwen по словарю и профилю search-train, затем строго валидировать колонки/операции. Код генерируется из доверенных блоков. Никаких внешних CSV, готовых ответов или кода с новым pip.
6. Для AIDE-подобного поиска сделать ограниченное дерево config→изменение→результат, с откатом к лучшей ветви и учётом ошибок/ресурсов. Сравнить с последовательным поиском на ОДИНАКОВОМ наборе действий, числе fit и бюджете LLM/токенов. Иначе нельзя приписывать выигрыш дереву: причиной может быть просто больше попыток или другой портфель.
7. Реальные LLM-вызовы проводить через существующий ограниченный прокси; обе политики получают одинаковые бюджеты. Не утверждать преимущество по одному красивому запуску; журналировать родители, действия, ошибки, вызовы/токены и выбранные конфиги.
8. Использовать существующие Runner/watchdog/метрики/CSV/упаковку. Микротесты нужны на отсутствие утечек, ограничения схем и корректность дерева; затем реальные проверки на обоих публичных кейсах. До открытия подтверждения заморозить гипотезы и ансамбль; помнить, что период 5 уже ранее исследован.
9. Итог: таблица «идея → поиск → подтверждение → стоимость → что взять в агент», отдельно объяснение работы AIDE в нашем проекте. Интегрировать полезное без условий по названиям публичных датасетов, проверить стандартный плоский ZIP, сохранить результаты и опубликовать проверенный код в репозитории.

Не нужны новые уточнения по API/пути/дедлайну: известное собрано выше. При реальном блокере действовать по текущим инструментальным ограничениям и честно сообщать, что не удалось проверить.
